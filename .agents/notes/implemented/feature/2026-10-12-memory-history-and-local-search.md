# Agent Note: 记忆撤销、主动记住与本地搜索

Status: implemented

## Problem

自动记忆缺少变更依据与恢复入口。用户无法主动选择需要记住的消息，历史列表也无法按正文查找旧对话。

## Decision

在现有 settings 表保存最近 30 次真实记忆变更，记忆正文与记录在同一事务提交。记录包含变更前后、时间及来源；一键撤销仅作用于最新记录，并校验当前正文，防止旧界面覆盖后续编辑。撤销本身也记录，清除全部数据同时删除记录，不增加数据库版本或依赖。

完整的用户文字消息沿用长按与右键菜单提供“记住这件事”。复用现有 metadata 模式合并稳定事实，禁用标题生成，不使用助手文字推断用户事实。手动编辑、切换、撤回、新对话、停止及卸载取消未完成请求，存储时重新核验来源消息和记忆快照。无新增事实时提示未发生变化，超出完整原文预算时保留原有记忆。

历史面板提供本地字面包含搜索，覆盖标题与数据库中全部用户、助手正文。搜索忽略大小写，每个会话展示一个结果及匹配正文片段，选择结果打开会话。结果按会话更新时间排序，异步旧结果不覆盖新查询。

## Alternatives considered

- 独立历史表及全文索引：当前最多 30 个本地会话，额外迁移与索引维护没有必要。
- 直接追加整条消息：会保存临时内容、引用和重复事实，继续复用模型整理规则。
- 撤销任意旧记录：容易覆盖后续修改，仅允许撤销最新变更。

## Consequences

- 手动编辑、清除、自动整理和主动记住的真实变更均可查看，重复保存不产生记录。历史读取校验来源类型、有效日期范围及重复标识，保留已有长手动记忆。
- 撤销和清空刷新后保持一致；旧记录、取消请求和已撤回消息不能覆盖当前记忆。撤销期间保护未保存的编辑草稿。
- 手机长按、桌面右键可主动记住完整用户文字消息，键盘可使用聚焦时显示的原生按钮；助手消息不显示该动作。
- 搜索覆盖未加载到聊天窗口的正文，处理空查询、无结果、读取失败和查询竞态。输入防抖 150 毫秒，逐消息扫描不将全部历史载入内存，返回命中附近片段。
- 界面文案中日同步，样式沿用现有面板；前端实现位于 src/，单元测试相邻，浏览器回归位于 e2e/。服务端协议与 Android 工程保持兼容。
- 主动记住额外消耗一次当前模型请求，模型可能认为所选内容没有新的稳定事实。记录保存在当前设备，最近 30 次之外的版本不保留。
