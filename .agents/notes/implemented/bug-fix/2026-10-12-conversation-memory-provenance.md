# Agent Note: 删除会话同步清理来源记忆

Status: implemented

## Problem

长期记忆以跨会话合并的全文保存，删除会话只清理消息与图片。全文快照无法精确剥离较早会话的事实，恢复旧快照又可能覆盖其他会话的新信息。

## Decision

- 在既有 settings 表保存 `userMemorySources`：`independent` 存放无来源旧记忆或手动替换的正文，`conversations` 按会话 ID 保存各自的完整事实集合。无需新增数据库版本或索引。读取时校验来源结构及其与共享正文的一致性，损坏或不匹配的数据按无来源正文保留。
- 自动整理与主动记住只向模型传入当前会话的 `existingMemory`，模型输出也只替换当前来源。仓库仍以整理前的共享正文校验过期请求，返回合并后的共享记忆供控制器更新。普通聊天继续跨会话共享，沿用 3000 字注入上限。
- 共享正文按独立记忆、会话来源的保存顺序合并，相同行仅在展示中去重，来源信息不去重。会话之间不做语义覆盖；纠正或忘记操作只修改当前来源。手动替换整份记忆形成独立正文；保存完全相同的正文是无操作，不改变归属。
- 变更历史保存前后来源快照，撤销与连续消息撤回同时恢复来源。历史仍最多保留 30 条，来源存储独立于历史上限，因此删除任意现存会话不依赖历史仍有该会话的记录。
- 删除在同一事务中清理会话、消息、图片、该会话的来源以及相关变更记录。其他历史记录的前后正文与来源快照也移除该会话，避免撤销其他变更时恢复已删事实。事务返回提交后的共享正文，控制器取消后台整理、同步正文和历史，再由 App 选择剩余会话或创建新会话。
- 旧版无来源数据只复用 `recallMessagesFrom` 安全恢复仍匹配当前记忆、属于待删除消息的连续最新快照；无法归属的混合旧记忆保留为独立正文。已删除来源或缺失快照的旧事实无法自动恢复归属。

## Alternatives considered

- 只取消后台请求：不能清理已提交记忆。
- 仅回退最新全文：不能删除较早会话，且会丢失后续有效事实。
- 按字符串差异推断旧事实来源：模型会改写、合并和纠正文本，文本差异不能可靠代表事实归属。
- 删除时重新调用模型整理全部剩余聊天：依赖网络与额度，无法保证完整覆盖长历史，也会重复抽取用户已主动清除的信息。

## Consequences

新保存的事实始终有会话来源；同一事实存在多个来源时，删除其中一个仍保留其他来源。删除与记忆清理原子提交，失败保留原数据。来源快照增加本地历史占用，受最多 30 个会话、每个自动来源 2000 字及 30 条历史的现有限制约束。旧版无法归属的内容不会因删除某个聊天而被猜测性清除。
