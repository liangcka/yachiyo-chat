# Agent Note: 撤回消息同步恢复记忆

Status: implemented

## Problem

撤回会取消后台记忆请求并删除消息，但已提交的自动记忆或主动记住结果仍存储在全局记忆中，后续聊天继续使用已撤回的事实。

## Decision

- 仓库通过 `recallMessagesFrom` 在同一个 Dexie 事务中删除消息、处理摘要水位线并恢复相关记忆，返回提交后的记忆正文。控制器等待事务完成后同步内存状态。
- 回滚复用既有记忆变更记录。仅从最新记录开始，连续恢复来源为 `automatic` 或 `message`、会话与待删除消息匹配、`after` 与当前记忆相等的更新。自动整理关联助手回复，主动记住关联用户消息。
- 已回滚的记录从历史中移除，使连续撤回能逐轮恢复，也避免已失效记录被再次撤销。
- 撤回首先取消后台请求。未提交写入由取消信号中止；已提交但尚未返回的写入由撤回事务恢复，迟到回调不得更新界面。
- 仓库接口保留可选能力，既有不管理长期记忆的适配器仍使用原消息删除方法。重新生成继续沿用原有入口；删除会话按[会话来源记忆契约](2026-10-12-conversation-memory-provenance.md)清理来源与历史快照。

## Alternatives considered

- 仅取消模型请求：不能恢复已提交的记忆。
- 仅修改界面状态：刷新页面后会重新读取错误记忆。
- 删除消息后分别恢复记忆：存储失败会留下消息与记忆不一致的状态。
- 跨越独立更新恢复旧全文快照：会覆盖其他消息、会话或手动保存的有效事实，因此回滚在独立更新处停止。

## Consequences

本轮消息产生的连续记忆更新随撤回一起恢复，先前记忆继续保留。存储结构与服务端协议不变。历史仍受既有 30 条上限约束；超过保留范围或已被独立更新合并的旧事实，不能通过全文快照安全地单独撤销。本机制不清理在旧版本中已经删除来源消息的记忆。
