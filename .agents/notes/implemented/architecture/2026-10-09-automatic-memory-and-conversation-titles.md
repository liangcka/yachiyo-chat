# Agent Note: 自动长期记忆与会话标题

Status: implemented

## Problem

长期画像随上下文压缩更新，短会话无法及时保存偏好。摘要选取最新历史再推进边界，会遗漏未覆盖的早期消息。会话标题缺少模型生成入口。

## Decision

完整回复落库后通过既有 `/api/chat` 的 `metadata` 模式后台整理当前回合。专用提示词输出 `{title, memory}`，分别允许 `null` 表示不改动。标题只填写尚未命名的会话，最长 24 个 Unicode 字符；长期记忆最多 2000 字，合并明确的稳定事实、去重、以新纠正替换旧信息。现有本地文本存储和手动编辑保持兼容。

自动记忆以当前会话为来源，每个来源最多 2000 字。整理请求只携带该来源的旧事实，普通聊天使用各来源合并后的共享记忆；删除会话同步清理该来源。来源存储、旧数据兼容与历史快照契约见[删除会话同步清理来源记忆](../bug-fix/2026-10-12-conversation-memory-provenance.md)。

请求用三条独立的用户 JSON 消息承载控制参数、用户原文与助手回复，服务端校验结构。只有完整用户原文在单条 4000 字预算内时才整理长期记忆，避免截断末尾的纠正或引用限定；助手回复仅辅助标题，不作为用户事实的依据。整理请求不联网，不携带聊天技能，复用当前模型配置。

领域模块负责解析与预算，仓库事务核验来源回复仍为最新完整消息、标题来源及记忆快照，控制器负责请求与取消。后台结果不得覆盖手动修改，不阻塞聊天，不产生聊天气泡。新一轮、停止、撤回、切换、卸载、离线及手动编辑取消过期整理；30 秒超时和取消信号覆盖模型请求及数据库事务等待与提交阶段。流式回复落库期间的取消同样阻止启动整理。

摘要压缩独立维护会话前情，从数据库最早未压缩的连续前缀分批整理，保留最新完整回合与跨边界的同时间戳消息。所有批次成功后一次保存摘要及边界，拒绝截断或格式损坏的结果；原始消息保留。撤销涉及已压缩消息时失效对应摘要，不自动回滚共享的长期记忆。

## Alternatives considered

- 继续在压缩时生成长期画像：无法覆盖短对话，容易重复抽取用户已删除的信息。
- 引入向量数据库：当前个人本地聊天不需要额外基础设施。
- 每次重新生成会话标题：会干扰查找和人工命名。

## Consequences

- 每个成功回合增加一次所选模型的后台请求，消耗相应额度；模型事实抽取仍可能出错，保留人工编辑入口。
- 跨会话记忆与会话摘要独立维护，手动清除的旧事实不会从历史压缩中重新抽取。
- 超过自动预算的旧手工记忆保持原文，不自动覆盖；普通聊天最多注入前 3000 字，避免突破请求边界。
- 两个记忆入口共享编辑器，后台变化不覆盖正在编辑的草稿；清除操作直接保存空记忆。
- 标题生成与记忆更新失败不会阻断聊天，下个完整回合重新整理当前回合。
