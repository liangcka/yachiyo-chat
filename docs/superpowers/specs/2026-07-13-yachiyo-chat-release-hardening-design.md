# Yachiyo Chat 发布加固设计

日期：2026-07-13

状态：用户已逐节确认

## 1. 背景与目标

现有 `feature/yachiyo-chat` 已实现手机优先的 React PWA、Cloudflare Pages Functions、共享访问码、KV 尽力限流、StepFun 流式聊天、中日双语、拍照识图、本地历史、停止生成和离线只读。当前形态属于功能型 RC，主要缺口不是新增功能，而是已知正确性问题、移动端交互缺陷、浏览器验收、CI 和交付证据尚未闭环。

本轮目标是把仓库完善到“仓库内可验证的上线就绪”状态：关键缺陷修复、自动化质量门完整、部署前人工门槛明确。不会配置真实密钥、修改 Cloudflare 生产环境或执行生产部署。

## 2. 已确认约束

- 保留 React、TypeScript、Vite、IndexedDB、Cloudflare Pages Functions、KV 和 PWA 架构。
- 保留少量朋友共享访问码的使用方式，不增加账号系统。
- KV 继续承担尽力防滥用计数，不把它描述为严格计费边界。
- 不改变深蓝星空、磨砂玻璃、430 像素桌面列宽和现有主要构图。
- UI 改动只服务于布局、软键盘、焦点、滚动、状态一致性、错误反馈和可访问性。
- 不实现语音、跨设备同步、云端历史、严格额度或逐设备会话撤销。
- GitHub Private 仓库为 `https://github.com/liangcka/yachiyo-chat`；全部验证通过前不推送未完成结果到 `main`。

## 3. 方案选择

采用“定向发布加固”：保留现有模块边界，围绕已确认问题进行小范围修复，并为每项行为变更补回归测试。

未采用以下方案：

- 验证体系优先：会让当前已知缺陷和 Windows 中文路径兼容问题污染初始基线。
- 架构重整：拆分整个 App、迁移严格计数设施或重新设计 UI 会显著扩大范围和回归风险。

## 4. 架构与组件边界

### 4.1 服务端正确性

保持 `/api/session`、`/api/chat` 和浏览器 SSE 事件协议不变，只修复边界行为：

- StepFun 流必须观察到 `[DONE]` 才能正常完成；正常 EOF 前缺少 `[DONE]` 视为提供商流错误。
- 恰好 200 个 Unicode 字符且随后收到 `[DONE]` 时正常完成；只有观察到第 201 个字符时才标记截断。
- JSON 与 SSE Functions 响应统一包含 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。
- 客户端仍只接收稳定错误码，不透传上游错误正文、凭据或绑定信息。

### 4.2 本地验证状态

在现有 IndexedDB 设置中保存一个非敏感的“本设备曾成功验证”标记：

- 在线启动时，服务端会话检查始终具有权威性。
- 离线启动时，只有存在本地标记的设备进入只读历史；首次使用或显式退出后的设备显示“首次验证需要联网”。
- 成功输入访问码后写入标记。
- 显式退出时清除标记和 Cookie，但不删除本地聊天记录。
- “清除本地数据”只删除会话、消息和图片，并保留当前语言与设备验证标记；清除数据不等同于退出。
- 在线会话过期时回到门禁，不静默删除历史或本地标记。

### 4.3 图片待发送状态

`pendingImage` 是待发送图片的唯一状态来源。缩略图 URL 从该 Blob 派生，并在替换或卸载时释放。新建会话、切换历史、成功发送和移除图片都清除同一状态，避免 UI 仍显示已失效图片。

### 4.4 弹层与焦点

从现有菜单行为中提取最小共享焦点管理逻辑，供菜单和历史面板复用：

- 打开时聚焦首个合适控件。
- Tab/Shift+Tab 限制在当前弹层。
- Escape 和遮罩点击关闭。
- 背景内容在弹层打开时不可交互。
- 关闭后把焦点归还给原触发控件。

现有 DOM 层级、样式类和视觉形态保持不变，不引入新的弹层设计系统。

### 4.5 移动可见视口

增加对 `window.visualViewport` 的轻量监听，将实时可见高度写入应用 CSS 变量，并在支持的浏览器中启用 viewport 的 `interactive-widget=resizes-content` 策略。软键盘打开时取消会把底部操作区推出可见区域的固定最小高度；桌面布局仍保持居中和最大 430 像素宽。

### 4.6 消息滚动

消息区记录用户是否靠近底部：

- 首次加载和用户发送新消息时滚到底部。
- 流式增量只在用户仍靠近底部时自动跟随。
- 用户向上阅读时不抢回滚动位置；重新滚到底部后恢复跟随。
- `prefers-reduced-motion` 下使用即时滚动，不执行平滑动画。

### 4.7 可访问性与异步错误

- 隐藏的文件输入不成为第二个不可见 Tab 停靠点；可见拍照按钮仍是唯一键盘入口。
- 图片移除、历史编辑/删除和更新关闭等目标拥有至少 44×44 CSS 像素的可点击区域，同时尽量保持原有视觉尺寸。
- 纯图片消息和缩略图提供本地化的可访问名称。
- 首版占位功能在点击和键盘聚焦时都提供“即将开放”说明。
- IndexedDB 读取、重命名、删除、清空、会话退出和图片加载均捕获异常，显示本地化 Toast，不产生未处理 Promise rejection。

## 5. 安全、隐私与限流

- 保留共享访问码、30 天无状态签名 Cookie 和 KV 尽力限流。
- 会话签名密钥由 `SESSION_SIGNING_SECRET` 与当前 `ACCESS_CODE_SHA256` 派生；轮换任一 Secret 都会使此前签发的所有会话失效，Cookie 负载不暴露访问码摘要。
- 不增加逐设备撤销表；退出只能立即清除当前浏览器 Cookie，这一限制在 README 中明确说明。
- README 明确 KV 的最终一致性与非原子计数意味着它不是严格计费边界；部署必须另外配置 Cloudflare 边缘限速及 StepFun 硬预算/告警。
- 在现有门禁或菜单中加入简短、非阻断式隐私说明：发送的文字和图片会交给 StepFun 处理，并提供其政策入口。
- 不在仓库、构建产物、日志、浏览器存储或测试夹具中加入真实访问码、API Key 或会话签名密钥。

## 6. 测试设计

每项行为修改遵循“失败回归测试 → 最小实现 → 全套验证”。

### 6.1 单元与组件测试

覆盖：

- 首次离线、已验证设备离线、显式退出后离线。
- 图片预览在发送、切换、新建和移除后的清理。
- 用户滚离底部时不被流式增量拉回，以及减少动态效果。
- 历史面板的 Escape、焦点圈定、背景隔离和焦点归还。
- 可见视口高度更新及事件清理。
- 44 像素触控目标、隐藏文件输入焦点和图片可访问名称。
- IndexedDB 与会话操作失败时的本地化错误反馈。

### 6.2 Functions 测试

覆盖：

- 完整 delta 后在 `[DONE]` 前 EOF。
- 恰好 200 字符后 `[DONE]`。
- 第 201 个字符触发截断。
- 访问码轮换后旧 Cookie 被拒绝。
- JSON/SSE 响应的 `no-store` 与 `nosniff`。

### 6.3 浏览器验收

- 390×844 使用受版本控制的 `toHaveScreenshot` 视觉基线。
- 320、375、390、430、768、1024 和 1440 宽度均验证无横向溢出、输入区可见、弹层可操作。
- 验证登录、Mock 流式回复、停止、历史恢复、中日切换、离线刷新、焦点顺序、Escape、Service Worker 接管和控制台零错误。
- 自动化只声明 Chromium 可证明的结果。真实 iOS/Android 软键盘和手机相机列为部署前人工检查，不伪装成已自动验收。

## 7. CI 与交付

GitHub Actions 在 `main` 推送和 Pull Request 上运行：

1. 安装固定 Node 22 与 `npm ci`。
2. 运行客户端和 Functions 测试。
3. 运行类型检查与 Lint。
4. 运行生产构建与泄密扫描。
5. 安装 Chromium 并运行 E2E；失败时上传 Playwright 报告和 Trace。

Cloudflare Workers 测试在 Linux 的纯 ASCII CI 路径中运行，其结果作为权威验证；README 保留 Windows 中文物理路径的已知限制及规避说明。

改动按服务端正确性、状态/UI、浏览器验收、CI/文档拆成原子提交。全部质量门通过后，将 `feature/yachiyo-chat` 快进合入 `main` 并推送到 Private GitHub 仓库。Cloudflare 生产绑定、真实 StepFun canary、密钥轮换、边缘限速和预算告警仍是部署前人工门槛。

## 8. 验收标准

1. 既有文字、图片、历史、中日切换、停止生成和 PWA 功能无回归。
2. 上游流缺少 `[DONE]` 时不会把部分回复保存为成功。
3. 恰好 200 字符可正常完成，第 201 个字符才触发截断。
4. 全新或已退出设备离线时不能跳过首次验证；已验证设备仍可离线阅读本地历史。
5. 切换或新建会话后不存在失效图片预览。
6. 用户向上阅读时流式回复不抢回滚动位置。
7. 历史弹层满足键盘焦点、Escape、背景隔离和焦点归还要求。
8. 移动软键盘打开时输入区仍处于可操作区域，且主要视觉方向不变。
9. 已确认的小型交互目标满足 44×44 CSS 像素要求。
10. 异步本地操作失败时有本地化反馈且控制台无未处理异常。
11. 390×844 视觉基线通过，全部规格宽度无横向溢出。
12. 单元、Functions、类型、Lint、构建、泄密扫描和 Chromium E2E 在 CI 中全部通过。
13. `dist/` 静态产物与 Git 历史中不存在真实密钥、共享访问码或公开角色提示词副本；角色提示词只允许存在于受版本控制的规范源文件和服务端 Functions 构建输入/包中。

## 9. 明确非目标

- 不新增语音、TTS、ASR 或实时音频。
- 不新增独立账号、社交登录或跨设备同步。
- 不把 KV 改造成严格配额系统，也不引入 Durable Object/D1 计数器。
- 不全面拆分 `App.tsx` 或重写 Controller、IndexedDB、PWA 和 i18n。
- 不重新设计配色、星空、玻璃层级、主要组件构图或桌面外观。
- 不自动操作 Cloudflare 生产环境或真实 StepFun 凭据。
